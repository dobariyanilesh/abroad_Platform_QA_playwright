Developer guide only — do not build this modal

This is a prototype annotation. It is not a product feature, not an admin screen, and must not ship. It documents how Overview “Needs attention” rows should be computed and worded.

Needs attention — ruleset

Show this card only on published experiences (Upcoming or In progress), and only for items with a useful next action. Drafts use “What blocks publish” / recommended next steps. Completed experiences hide the card. If nothing matches, omit the card — do not show “All clear”.

When a row may appear

  • The gap is actionable — one click opens the exact Build or Manage workspace.
  • Someone is affected now, or will be as soon as they pay. Prep unlocks after enrollment form + payment (including $0).
  • The check is objective (empty, unset, count). No “needs review” without a review state.

Severity, counts, copy

  • Danger (red) — paid participants can already open an empty or broken surface.
  • Warn (gold) — incomplete but not yet visible, or ops follow-up (docs, balances, forms).
  • Badge count = number of rows on this card.
  • Departure-prep readiness number = Build prep misses only (checklist, itinerary, orientation). Roster items do not belong in that card.
  • Heading: Upcoming → “Before departure”. In progress → “Right now”.
  • Title is a countable fact. Supporting line says who is affected. CTA: Fix → empty content, Open → incomplete content, Set → orientation, Review → roster.

Never show

  • Learning Resource (optional).
  • RSVP, Partners, Main video, Testimonials.
  • Checklist that already has items — do not invent a “needs review” state.

Drafts — not this card

Publish blockers live under “What blocks publish” only: dates, public title, summary, shared price, header image, ≥1 slider image, inclusions, faculty, ≥1 journey phase, ≥1 FAQ, ≥1 interest question, signup copy, welcome email with {{ button }}, ≥1 enrollment question. Single occupancy, group size, location, learning, checklist, itinerary, and optional Content items are not publish blockers.

Production today has no readiness engine — publish is gated only on programme start/end. This ruleset is the intended v7 behaviour.
